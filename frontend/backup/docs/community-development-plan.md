# План развития community-платформы

## Цель

Развить проект как информационное сообщество для программистов: публикации, Q&A, динамическая активность, тренды, рекомендации, репутация, подписки, уведомления и встроенные интеллектуальные инструменты для авторов.

## Этап 1. Community UI foundation

- Основная навигация ориентирована на публикации, вопросы, теги, участников, тренды, уведомления и профиль.
- Главная страница показывает статистику, популярный контент, актуальные вопросы, теги, участников и активность.
- Профиль фокусируется на публикациях, вопросах, ответах, комментариях, сохранённом и репутации.

## Этап 2. Discovery layer

- `GET /community/discovery` — общая витрина данных главной страницы.
- `GET /community/trends` — тренды по периоду.
- `GET /community/recommendations` — рекомендации по контенту и тегам.
- `GET /community/users` — рейтинг и поиск участников.

## Этап 3. Activity Feed

- `community_activities` хранит действия участников.
- В ленту попадают публикации, вопросы, ответы, принятые решения, комментарии, реакции, подписки и изменения репутации.
- `GET /community/activities` отдаёт последние события для главной страницы и будущих профилей.

## Этап 4. Интеллектуальные инструменты

- `POST /ai/search` — поиск материалов по естественному запросу.
- `POST /ai/question/assist` — анализ вопроса, проверка структуры, подбор тегов и похожих вопросов.
- `POST /ai/publication/assist` — анализ публикации, план, описание, теги и редакторские подсказки.
- `POST /ai/issues/{issueQuestion}/answer-draft` — предварительный ответ для Q&A с явной пометкой автоматической генерации.

## Этап 5. Редакторы

- Конструктор вопроса получает встроенный анализ качества вопроса и рекомендации.
- Конструктор публикации получает встроенный анализ структуры, подсказки и автодобавление плана.
- Следующий шаг — добавить специализированные блоки для diff, terminal, file tree и embed-ссылок на материалы платформы.

## Этап 6. Песочница кода

- Вынести запуск кода из учебного сценария в самостоятельный инструмент сообщества.
- Связать сниппеты с вопросами, ответами и публикациями.

## Step 5 — Technical content builders

The publication and Q&A builders now support programming-oriented blocks:

- `terminal` — command, shell, working directory and output;
- `diff` — patch fragments with filename and diff highlighting;
- `file_tree` — project/module structure;
- `callout` — structured notes, tips, warnings and conclusions.

These blocks are supported by backend enums, validation, API resources, frontend types, editors, previews, renderers and seed data.
